# Agents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every model-driven job an identity (an agent), show each one in Admin with its calls, inputs, outputs, activity, instructions and settings, and add a Watcher agent that records incidents.

**Architecture:** A static registry of `AgentDefinition`s describes the four existing pipelines without changing how they run; `llm_calls.step` is the agent id. New read routes group stored calls into runs and derive a one-line result for each; two additive tables hold change/rerun events and incidents. The Watcher is a once-a-minute pass inside the api that evaluates pure rules over facts read from the database and the health probes.

**Tech Stack:** TypeScript, Express 5, zod 4, pg, vitest (backend); Next.js 16 server components and server actions, Tailwind, vitest (frontend); bash (`ops/ct`).

**Spec:** `docs/superpowers/specs/2026-11-12-agents-design.md`. Approved look: `docs/superpowers/specs/2026-11-12-agents-mockup.html` (open in a browser).

## Global Constraints

- The tracker, namer, extractor and summarizer keep their loops, tables and cursors. No task edits `backend/src/ingest/{tracker,namer,extractor,summarizer,gap-filler,session-runner,sweeper}.ts` or `backend/src/agents/{extract,name,track,summarize,structured}.ts` except where a task names the exact line of change.
- Nothing inserts an `llm_calls` row with `step = 'extract'` that is not a real extraction window.
- Migrations are additive only: new tables, new indexes, nothing dropped, renamed or tightened.
- Every new route sits behind `requireCaller` (mounted after it in `backend/src/app.ts`).
- No cost is shown anywhere in the new Admin pages.
- Admin look: existing theme tokens only (`text-ink`, `text-ink-soft`, `border-line`, `bg-surface`, `text-live`, `text-accent`), one line per thing, a status dot, detail on a click. A row on the overview navigates to the agent's page; it does not expand in place.
- Run commands inside `backend/` or `frontend/`, never at the repo root. Backend tests need `docker compose -f compose.local.yaml up -d postgres`.
- Read `frontend/AGENTS.md` and the Next.js docs it points to before writing frontend code.
- Commit after each task. **Do not push without the owner's yes**: a push to `main` deploys. Pushes happen only at the four checkpoints below, and never with `[deploy-now]`.
- Verification on prod uses the two Solana Accelerate recordings as test videos and `ops/ct` (reads are free; never print `frontend/.env.prod`).

## Review Focus

1. An agent with no calls at all (the Watcher on day one, any agent on a fresh database): the overview and its page render, the strip is empty, "has not run yet". Pinned in Task 3 and Task 4.
2. A call whose input is very large (a summarizer call holds a whole transcript): lists never carry `input` or `output`; the call window scrolls inside itself. Pinned in Task 2 and Task 5.
3. A video's stored config naming a prompt version that no longer exists, or holding a value its schema rejects: `GET /agents/:id` still answers and reports the value as stored. Pinned in Task 3.
4. A settings patch with a key the agent does not own, or one bad value among good ones, applied to "all": refused with 400 and nothing is written to the default or to any video. Pinned in Task 11.
5. A Watcher pass that throws, overlaps the previous one, or runs first after an api restart while an incident is already open: the timer survives, passes never overlap, and no second open incident appears for the same rule, agent and video. Pinned in Task 7.

```ts
export interface CallEffects {
  claims: number;                    // rows in claims with this call_id
  named: { voice: string; name: string }[]; // name proposals of this call that were accepted
  switchedTo: string | null;         // title of the talk whose talk_spans row has this call_id; null when none
  summaryOf: string | null;          // title of the talk whose talk_summaries row has this call_id
}
export interface AgentDefinition {
  id: string; name: string; role: string;
  trigger: { text: string; intervalKey?: string };
  reads: string[]; writes: string[];
  settings: z.ZodObject | null;
  settingsScope: "video" | "global";
  promptKey?: string; modelKey?: string;
  fixedAtStart: string[];
  output: z.ZodType | null;
  internal: boolean;
  describe(call: { error: string | null; parsed: unknown }, effects: CallEffects): string;
}
```

- Produces, in `registry.ts`: `AGENTS: AgentDefinition[]` (order: track, name, extract, summarize, watch), `agentById(id: string): AgentDefinition | null`, `agentForKey(settingKey: string): AgentDefinition | null`.
- Produces, in `contracts-agents.ts`: `RunStatus = z.enum(["ok","failed","slow"])`; `WatchSettings` (below); `AgentCard`, `AgentDetail`, `RunSummary`, `AgentEvent`, `Incident`, `Rerun` (shapes given in the tasks that answer with them).

Values the definitions pin:

| id | name | role | settings | promptKey / modelKey | intervalKey | fixedAtStart | output | internal |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `track` | Tracker | Works out which session is on stage. | `TrackConfig` | `track_prompt` / `track_model` | `track_interval_s` | `track`, `track_interval_s` | `TrackOutput` | false |
| `name` | Namer | Works out who each voice is. | `NameConfig` | `name_prompt` / `name_model` | `name_interval_s` | `name`, `name_interval_s` | `NameOutput` | false |
| `extract` | Extractor | Pulls the claims out of what is said on stage. | `ExtractConfig` | `extract_prompt` / `extract_model` | `extract_interval_s` | `extract`, `extract_interval_s` | `ExtractOutput` | false |
| `summarize` | Summarizer | Writes up a session when it leaves the stage. | `SummaryConfig` | `summary_prompt` / `summary_model` | none | (empty) | null | false |
| `watch` | Watcher | Notices when something goes wrong and records it. | `WatchSettings` | `watch_prompt` / `watch_model` | none | (empty) | `WatchOutput` | true |

`describe` returns, first match wins: any agent with `error` → `Failed: ` + first 80 characters of the error. Extractor: `No claims`, `1 claim`, `N claims`. Namer: `Named S2 as Kevin B.` (+ ` and N more`), else `No one named`. Tracker: `Switched to "<title>"` when `switchedTo`; else from `parsed.state`: `Still on the same session`, `Break`, `Not sure`. Summarizer: `Wrote "<parsed.headline>"`. Watcher: first 80 characters of `parsed.cause`.

`WatchSettings` (zod, every key defaulted): `enabled: true`, `fail_runs: 3`, `slow_runs: 3`, `quiet_intervals: 5`, `slow_ms: { track: 60000, name: 60000, extract: 60000, summarize: 180000, watch: 60000 }`, `probe_passes: 2`, `box_stale_s: 600`, `clear_passes: 3`, `diagnose: true`, `watch_model: "haiku"`, `watch_prompt: "v1"`. `WatchOutput = z.object({ cause: z.string().min(1), fix: z.string().min(1) })`.

Migration `014_agents.sql`:

```sql
create table agent_events (
  id bigserial primary key,
  agent_id text not null,
  session_id uuid references sessions (id) on delete cascade,
  call_id bigint references llm_calls (id) on delete cascade,
  kind text not null check (kind in ('change', 'rerun')),
  summary text not null,
  data jsonb not null default '{}',
  actor text not null default 'unknown',
  created_at timestamptz not null default now()
);
create index agent_events_agent on agent_events (agent_id, id desc);

create table incidents (
  id bigserial primary key,
  rule text not null,
  agent_id text,
  session_id uuid references sessions (id) on delete cascade,
  call_id bigint references llm_calls (id) on delete set null,
  parent_id bigint references incidents (id) on delete set null,
  title text not null,
  detail text not null default '',
  diagnosis text,
  first_seen timestamptz not null default now(),
  last_seen timestamptz not null default now(),
  count int not null default 1,
  clear_passes int not null default 0,
  resolved_at timestamptz
);
create unique index incidents_open on incidents (rule, coalesce(agent_id, ''), coalesce(session_id, '00000000-0000-0000-0000-000000000000'::uuid)) where resolved_at is null;
create index llm_calls_step on llm_calls (step, id desc);
```

Check how `DELETE /sessions/:id` removes a video's rows (`repositories/sessions.ts` `remove`) and confirm the cascades above fit it; if it deletes child tables by hand, add these two there instead of relying on cascade.

```ts
export interface RunRow { id: number; session_id: string; step: string; prompt_version: string; model: string;
  window_t0: number; window_t1: number; attempt: number; latency_ms: number; error: string | null; parsed: unknown; created_at: string }
export function statusOf(run: { error: string | null; latency_ms: number }, slowMs: number): RunStatus; // failed beats slow
export async function listRuns(db, opts: { agentId: string; sessionId?: string; status?: "failed" | "slow"; before?: number; limit: number; slowMs: number }): Promise<RunRow[]>; // newest first
export async function recentStatuses(db, agentId: string, n: number, slowMs: number): Promise<{ status: RunStatus; at: string }[]>; // oldest first
export async function effectsFor(db, callIds: number[]): Promise<Map<number, CallEffects>>;
export async function attemptsOf(db, callId: number): Promise<number[]>; // ids of every attempt of that call's run, oldest first
```

A row is a run's last attempt when no later row has the same `session_id`, `step`, `window_t0`, `window_t1` and `attempt = this.attempt + 1`. `listRuns` selects no `input` and no `output`. `effectsFor` is one query per effect table for the whole id list, not one per call; read `repositories/names.ts`, `spans.ts` and `summaries.ts` for the columns that mark a proposal accepted and link a span or summary to a call and a talk.

```ts
AgentCard = { id, name, role, trigger: string, internal: boolean, prompt_version: string | null, model: string | null,
  status: "ok" | "failed" | "slow" | "idle", last_run_at: string | null, recent: RunStatus[] /* ≤ 24, oldest first */, open_incidents: number }
AgentDetail = AgentCard & { reads: string[], writes: string[], settings_scope: "video" | "global",
  settings: { key: string, value: unknown, default: unknown, fixed_at_start: boolean, valid: boolean }[],
  instructions: { version: string, source: "file" | "registered" | "registered over the file", model: string, in_use: boolean, exists: boolean }[] }
RunSummary = { id, session_id, session_title: string | null, prompt_version, model, window_t0, window_t1, attempt, latency_ms, error, status: RunStatus, result: string, created_at }
```

- `GET /agents` → `AgentCard[]`. `status`: `failed` when the agent has an open incident or its newest run failed; else `slow` when its newest run is slow; else `idle` when it has no runs; else `ok`. `prompt_version` and `model` are what a new video would use (code default under the stored default config; the Watcher's from its own settings). `open_incidents` counts `incidents` rows with that `agent_id` and no `resolved_at`.
- `GET /agents/:id` → `AgentDetail`, 404 for an unknown id. A stored value its schema rejects is returned as stored with `valid: false`. When the version in use is not among the known versions, it is appended to `instructions` with `exists: false`.
- `GET /agents/:id/calls?session=&status=&before=&limit=` → `RunSummary[]`; `limit` default 50, max 200; `status` other than `failed`/`slow` is ignored.
- `GET /calls/:id` keeps `call`, `claims`, `proposals` and gains `result: string`, `status: RunStatus`, `attempts: LlmCall[]` (the whole run, oldest first) and `events: AgentEvent[]` (empty until Task 10).

```ts
export interface Finding { rule: Rule; agentId: string | null; sessionId: string | null; callId: number | null; title: string; detail: string; parentRule: Rule | null }
export interface WatchFacts {
  videos: { id: string; title: string; status: string; attention: string | null; isReplay: boolean; transcriptT: number;
            config: Record<string, unknown>;
            agents: Record<string, { runs: { id: number; status: RunStatus; error: string | null }[] /* newest first, ≤ 10 */; lastWindowT1: number }> }[];
  proxyFails: number; speechFails: number;   // consecutive failed probes, this pass included
  box: { ageS: number | null; failed: string | null };
}
export function evaluate(facts: WatchFacts, settings: WatchSettings, agents: AgentDefinition[]): Finding[];
```

Rules, exactly:
- Replays (`isReplay`) produce no findings.
- `agent_failing`: the newest `fail_runs` runs of an agent on a video are all `failed`. `callId` the newest. Title `<Name> failed <n> times in a row on <video title>`; detail the newest error. `parentRule: "proxy_down"`.
- `agent_slow`: the newest `slow_runs` runs all `slow`. Title `<Name> is slow on <video title>`. `parentRule: "proxy_down"`.
- `agent_quiet`: only for `track` and `extract`, only when the video's status is `live` and the agent's on/off setting in the video's config is not `false`: `transcriptT - lastWindowT1 > quiet_intervals × <its interval from the video's config, default from its schema>`. Title `<Name> has gone quiet on <video title>`. `parentRule: "proxy_down"`.
- `video_attention`: `attention` is not null. Title `<video title> needs attention`; detail the attention text. `parentRule: "speech_down"`.
- `video_degraded`: status `degraded`. Title `<video title> stopped by itself`.
- `proxy_down` / `speech_down`: the counter ≥ `probe_passes`. Titles `The model proxy does not answer`, `Speech does not answer`.
- `box_stale`: `ageS` not null and `> box_stale_s`. Title `The box has stopped reporting`. A box that never reported (`ageS` null) is no finding.
- `deploy_failed`: `box.failed` is set. Title `A deploy failed`; detail the value.
- `parentRule` is kept on a finding only when a finding of that rule is in the same result; otherwise null.
