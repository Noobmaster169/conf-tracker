# A run that survives failures: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A video keeps going through API restarts, speech restarts, stream hiccups and model failures: it resumes from
the last stored second on the same video, catches up what it missed, and never skips or repeats a stretch.

**Architecture:** The speech service learns to start a session at a stream second (`start_at`), on the video's
absolute clock, and to carry its speaker registry across sessions on disk. The backend turns a video into a series of
legs: when a leg dies it cuts storage back to the resume point and opens the next leg from there, by itself, with
backoff. The loops live per video (not per leg), start from stored progress, and the extractor never skips. A sweeper
finishes backlogs and summaries for videos that are no longer running. Gaps (a live stream without rewind) are
recorded and filled from the recording after the stream ends.

**Tech Stack:** Python 3 / FastAPI / numpy / pytest (speech, in `/root/ai/fiber/yt-stream/speech`); TypeScript / Express
/ zod / Postgres / vitest (backend, `/root/ai/fiber/conf-tracker/backend`); Next.js (frontend,
`/root/ai/fiber/conf-tracker/frontend`).

**Spec:** `docs/superpowers/specs/2026-11-11-resume-design.md`

## Global Constraints

- Live for Breakpoint, 16 November 2026. Part A ships first (it restarts speech); Part B after; drills (Task B10) by 15 November.
- Every new speech protocol field is optional with a default that behaves exactly as today; yt-stream's backend must keep working unchanged.
- Never push to yt-stream `main` while any video (of either app) is running: its auto-deploy restarts speech. Check `GET /health` on conf-tracker (`live: []`) first.
- Push to GitHub over HTTPS with the gh helper and a timeout: `timeout 90 git -c credential.helper= -c credential.helper='!gh auth git-credential' push https://github.com/Noobmaster169/<repo>.git main:main` (port 22 is blocked here).
- yt-stream's working tree has someone else's uncommitted edits (`deploy/README.md`, `deploy/run-ngrok.sh`): never stage them; `git add` explicit paths only. Same rule in conf-tracker (`tmp/` is not ours).
- Commit style: `feat(scope): …` / `fix(scope): …`, a plain sentence, no attribution trailer, as in `git log`.
- Stream time is absolute everywhere: second 0 is the start of the broadcast or recording; a leg's times are already on that clock. Nothing in the backend adds offsets.
- Frame size is 0.5 s (8000 samples at 16 kHz); every `start_at` is rounded down to a multiple of 0.5 by speech, which reports the time it actually started at.
- Backoff for reopening a leg: 5, 10, 20, 40, then 60 s forever. "Needs attention" after 15 minutes of recovering. Catch-up speed cap default 3× real time (`catchup_max_speed`, revisited in B10).
- Tests: speech `pytest` in `speech/` (use the venv the README names, or `python -m pytest`); backend `pnpm test` in `backend/` (compose Postgres on 5435); frontend `pnpm test` in `frontend/`.

## Review Focus

1. Speech still holds the previous leg (socket closing) when the backend opens the next one with the same id: speech refuses it, and the backend treats the refusal as one more failed attempt and retries; it never gives up or opens two. Test in B4.
2. The admin presses stop while a retry is scheduled: no leg opens afterwards and the video stays stopped. Test in B4.
3. The API restarts while a video is `recovering` (its retry timer died with the process): boot resumes it too. Test in B5.
4. A resume `start_at` at or past the end of a recording (the recording is shorter than the stored transcript): speech ends the session with `source_ended` at once, and the backend stops the video instead of looping. Tests in A3 and B4.
5. The model is down when a stream ends: the final drain leaves the backlog, and the sweeper extracts it once the model is back, never skipping a window. Test in B6.
